# Craft 三種顯示方式：觀察與落地討論

日期：2026-10-20。透過使用者目前開啟的 macOS Craft 實際切換觀察；
同一資料夾比較列表、網格、瀑布，另以圖片／文字混合的文件交叉觀察。
未編輯文件內容，研究後將各資料夾的顯示模式恢復，返回原本資料夾的網格畫面。
本文件保留 0.1.24 時的研究紀錄。使用者已批准完整復現卡片預覽與三段式切換；
0.1.25 的實作與驗證見 CRAFT_025.md。下方原始「待定」項目已由該文件定稿。

## 實際看到的差異

| 模式 | 排列 | 文件卡片／列 |
| --- | --- | --- |
| 網格 | 等寬等高、逐列對齊 | 外形約 5:4，標題在上、分隔線、縮小的格式化文件預覽；長內容底部漸隱 |
| 瀑布 | 等欄寬、卡片高度不同，下方位置錯開 | 同樣是上方標題與文件預覽，預覽較長；短文件也可能保留大量留白，不是全文無上限展開 |
| 列表 | 等高橫列、淡分隔線 | 左側小文件縮圖，名稱與單行摘要，右側為上次瀏覽／更新／建立日期 |

資料夾在卡片模式以置中的資料夾圖示、名稱、項目數呈現。
圖片會出現在文件內容原本的位置，也能與多段文字、清單、連結卡片同時出現，
不是每份文件只抽第一張圖片當封面。

切換資料夾再返回時，觀察到各資料夾保留不同模式；沒有重啟 Craft 驗證持久化。
沒有取得 Craft 內部 DOM／布局演算法，不能將視覺觀察當成其程式實作證明。
沒有測試亮色、窄視窗或 iOS Craft；以下自適應設計是對 Visual Gallery 的提案。

## 對照目前 Visual Gallery

- Layout.ts、GalleryView.ts：目前是固定寬度 CSS Grid。鍵盤上下移動以欄數計算，
  瀑布／列表需要不同的幾何定位規則。
- ThumbnailService.ts：Markdown 指定 cover 或第一張內嵌圖片優先，否則只有最多
  220 字純文字摘要。這個資料不足以還原 Craft 的標題、清單、表格、圖片混排。
- CanvasThumbnailProvider 的快取結果已有寬高，但 GalleryThumbnail 介面目前未傳遞。
  多比例布局需要將尺寸傳到畫面，預留位置，減少縮圖載入後的跳動。
- CardSelection 與目前文件順序、原生歷史、內外拖入、右鍵選單需要共用，
  不應為每種模式複製另一套檔案操作。
- LocalState 可擴充本機每資料夾的模式／捲動位置；不應因切換顯示而改寫共享設定。
- docs/CARD_GEOMETRY.md 的單一裁切表面＋外側描邊契約繼續適用。
  新布局／新卡片樣式仍需通過 production build、實際 host 幾何與截圖矩陣。

## 建議的落地方式

1. 先定義三模式共用資料與互動：同一個排序、篩選、選取、開啟、拖放、歷史。
   切換模式保留選取，盡量用同一檔案作為捲動錨點。
2. 網格採統一尺寸；列表採小預覽＋名稱／摘要＋類型／日期，窄窗優先保留名稱。
   上次瀏覽不是現成檔案 metadata，若要仿 Craft 需另加本機紀錄，不能用 mtime 冒充。
3. 瀑布用可控的分欄定位，保留原始排序的 DOM／選取順序。載入前先決定高度，
   高度設上下限；避免單純 CSS 多欄造成欄優先的閱讀／鍵盤順序混淆。
   方向鍵依實際幾何找鄰近卡片，Shift 選取維持文件排序。
4. 筆記補獨立格式化預覽：渲染適量開頭 Markdown，保留清單／表格／本機圖片，
   縮小呈現並對過長內容漸隱。採懶載入、並行上限及卸載清理；避免大量卡片同時
   跑重型 Markdown 外掛。自訂 cover 的優先規則需先決定。
5. Canvas 保留整張 contain 縮圖；圖片瀑布可保留自然比例並限高；PDF 保留第一頁。
   這些是對 Visual Gallery 檔案種類的延伸，不是已觀察到的 Craft 規則。

## 尚待與使用者定稿

- 復現範圍：只加三種排列，或也改成「上方標題＋格式化文件預覽」的卡片？
  若以視覺接近 Craft 為目標，後者是關鍵。
- 工具列：現有規則只有新增／排序／篩選三個圖示。若加入 Craft 式三段顯示切換器，
  需明確定稿它的位置，以及對原三按鈕規則的調整；尚未新增任何按鈕。
- 是否每個資料夾保留自己的本機模式？建議是；預設網格。
- 有明確 cover 的筆記，是否仍優先顯示封面？列表是否需要上次瀏覽欄？

建議分兩個可驗收步驟：三模式與互動先成形，再補文件預覽與視覺細節；
只有完成第二步，卡片內容呈現才會接近此次看到的 Craft。
